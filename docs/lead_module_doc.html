1. Executive Summary & Architectural Overview

The Lead Module is the foundational CRM engine of myAgenci.ai. It orchestrates the entire lifecycle of prospects—from lead generation (via web forms, manual creation, CSV imports, and automated Facebook Lead Ads Graph API sync) through qualification, call tracking, product mapping, quotation building, and conversion into paying clients.

Architectural Highlights

  • Multi-Tenant Isolation: Built on the BelongsToCompany trait, enforcing strict company-level tenant boundaries.
  • Hierarchical Data Visibility: Scoped dynamically via DataVisibilityService across Company Admin, Branch Manager, Team Leader (TL), and Sales Executive levels.
  • Dynamic Field Engine: Supports extensible custom fields (LeadFormField & LeadFieldValue) per branch and tenant without database schema alterations.
  • Multi-Product Line Items: Supports multiple products/services per lead with custom pricing, discount approval workflows, and milestone payment tracking.
  • Omni-Channel Synchronization: Unified web dashboard paired with Sanctum-authenticated mobile REST API endpoints for Android and iOS apps.

2.6. Dynamic Custom Fields (lead_form_fields & lead_field_values)

Tenant admins can create dynamic custom fields per branch (e.g. "GST Number", "Annual Turnover", "Website URL") without running migrations. The data is persisted using an Entity-Attribute-Value (EAV) structure in lead_field_values.

3. Eloquent Models & Business Logic

3.1. App\Models\Lead Lifecycle Booting

protected static function booted(): void
{
    // 1. Global Branch Scoping for Branch Managers
    static::addGlobalScope('branch', function (Builder $builder) {
        if (! auth()->hasUser()) return;
        $user = auth()->user();
        if ($user && $user->isBranchAdmin()) {
            $branchIds = $user->getMyBranchIds();
            if (!empty($branchIds)) {
                $builder->whereIn($builder->getModel()->getTable() . '.branch_id', $branchIds);
            }
        }
    });

    // 2. Automated Attribute Assignment on Creation
    static::creating(function (Lead $lead) {
        if (!$lead->created_by && auth()->check()) {
            $lead->created_by = auth()->id();
        }
        if (!$lead->company_id && auth()->check()) {
            $lead->company_id = auth()->user()?->company_id;
        }
        if (!$lead->lead_date) {
            $lead->lead_date = now()->toDateString();
        }
    });
}

Key Query Scopes

  • scopeForUser($query, $userId): Restricts records to where assigned_to == $userId or created_by == $userId.
  • scopeForBranch($query, $branchId): Limits records strictly to a specified branch ID.
  • scopeConverted($query): Matches won leads using status IDs [5, 15] or status strings won / converted.
  • scopeLost($query): Filters lost / cancelled / not-interested leads.

4. Security & Role-Based Data Visibility (DataVisibilityService)

Visibility is centrally enforced by App\Services\DataVisibilityService::applyLeadVisibility($query). It ensures no user can access leads outside their authorized organizational hierarchy.

1. ACCESS_COMPANY (Company Admin / Director)

Complete company-wide visibility across all branches belonging to company_id.

2. ACCESS_BRANCH (Branch Manager)

Restricted to leads belonging to their assigned branch IDs configured in user_branches.

3. ACCESS_TEAM / TL (Team Leader)

Can access leads assigned to themselves and any sales reps reporting to them in user_mappings.

4. ACCESS_SELF (Sales Executive / Telecaller)

Strictly restricted to leads where assigned_to = auth()->id() or created_by = auth()->id().

6. Core Subsystems & Integrations

6.1. Untouched Leads Pipeline

Identifies inbound leads that have received 0 customer interactions to prevent leads from growing cold: 

SELECT * FROM leads 
WHERE id NOT IN (SELECT DISTINCT lead_id FROM lead_call_updates)
  AND lead_status NOT IN ('won', 'lost', 'cancelled')
ORDER BY lead_date DESC;

6.2. Facebook Lead Ads Auto-Import

Automated ingestion via App\Services\FacebookLeadImporter:

  • Queries Meta Graph API v19.0 using page access tokens from campaign_masters.
  • Maps form field keys to CRM fields via campaign_field_migrations.
  • Performs round-robin auto-assignment among active agents in assigned_users.
  • Automated via cron command: php artisan app:facebook-lead-integration.

6.3. CSV / Excel Bulk Lead Ingestion

Managed by LeadImportController: parses CSV headers, maps dynamic columns, detects phone number duplicates, and bulk-inserts rows inside safe database transactions.

6.4. Price Request Approval Workflow

Sales reps wishing to offer discounts below approved unit rates trigger a request to lead_product_price_requests. Upon approval by an Admin or Sales Head, product pricing, GST, and totals are automatically updated.

7. Developer & Extension Guidelines

7.1. Adding a New Column to the leads Table

  1. Migration: php artisan make:migration add_field_to_leads_table --table=leads
  2. Model: Add column to $fillable in App\Models\Lead.
  3. Form Requests: Add validation rules in StoreLeadRequest and UpdateLeadRequest.
  4. Blade Views: Add input in form.blade.php and display in show.blade.php.
  5. API Resource: Include attribute in LeadResource for mobile clients.
! IMPORTANT: Querying Leads Safely
Never query Lead::all() directly in controllers or services without passing through DataVisibilityService. Always invoke: 
$query = Lead::query();
app(DataVisibilityService::class)->applyLeadVisibility($query);
✓ TIP: Mobile Phone Number Regex & Search
Always validate phone numbers using Lead::MOBILE_NUMBER_REGEX (/^\+?[0-9]{7,15}$/). For AJAX lookups, sanitize search terms by stripping white spaces and non-digits to match international (+91) and domestic numbers seamlessly.
